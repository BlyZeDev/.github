# Contributing

Thanks for your interest in contributing! Every kind of help is welcome: bug reports, ideas, documentation and code.

## Reporting issues

Please use one of the issue templates and search existing issues first.

| Type | Use it for |
|---|---|
| 🐞 Bug | Something isn't working |
| 💡 Enhancement | New feature or improvement idea |
| 📖 Documentation | Missing, unclear or wrong docs |
| ❓ Question | Asking for help or information |
| 📝 Task | Maintenance, refactoring and other work items |

**Security problems:** do not open a public issue. Follow the [security policy](SECURITY.md).

## How issues are organized

- **Type** says what the issue is.
- **Status** says where it is: Triage, Backlog or Work in progress.
- **Priority** says how urgent it is: Critical, High, Medium or Low.
- **Area** says what it affects: Code Quality, Performance, Security, Reliability, Compatibility or Dependencies.
- **Labels** are used for special cases:
  - `Help wanted`: extra attention or contributions are welcome
  - `Invalid`: why an issue was closed

You don't need to set Status, Priority or Area yourself. I will do that while triaging.

## Contributing code

1. Look for issues labeled `Help wanted`, or open an issue first to discuss bigger changes.
2. Fork the repository and create a branch for your change.
3. Keep the change focused and follow the existing code style.
4. Test your change.
5. Open a pull request and describe what it does and why. Link the related issue, for example `Closes #123`.

## Improving documentation

Documentation fixes are very welcome. Small corrections can go straight into a pull request.

## Be kind

Please be respectful and constructive. Maintainers and contributors are all people with limited time.
